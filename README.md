# HEADLINE 60

**세상의 이슈, 60초면 충분해.** 로컬 Mac에서 블로그·뉴스 URL을 등록하면 원문 추출 → 근거 연결 → 대본 → 음성 → 720×1280 영상 → YouTube 비공개 업로드까지 순서대로 처리하는 개인용 스튜디오.

## URL 등록 큐 (기본 화면)

1. [관리 화면](http://127.0.0.1:8060)에서 블로그·뉴스 URL을 넣고 등록한다(목소리는 남성 내레이터 Ryan).
2. 등록 즉시 SQLite에 저장된다. 기다리지 않고 다음 URL을 계속 등록하면 된다.
3. 서버가 등록 순서대로 한 건씩 처리한다: 원문 본문 추출 → 원문 일치 발췌(공식 제목 포함) 자동 연결 → Ollama 대본(검사 실패 시 최대 3회, 무한 재시도 없음) → TTS(1.18배) → Reels v3 720p/30fps → YouTube **비공개** 업로드.
4. 목록에서 상태·단계·오류, 영상 미리보기, YouTube 링크, 재시도/취소를 확인한다. 한 건이 실패해도 다음 건은 계속 진행된다.
5. 작업 중에만 `caffeinate -i`로 자동 잠자기를 막는다(화면 잠금 중에도 계속). 서버가 재시작되면 중단된 항목은 저장된 단계부터 다시 진행된다.

- 자동 제작물은 사람이 승인하지 않은 **AI 초안 미리보기**다. 수치는 원문 발췌에 있는 값만 허용하지만 문장 의미까지 자동 검증하지는 않는다. 공개 전 YouTube Studio에서 내용을 직접 확인한다.
- 근거 ID는 내부에서 자동 연결한다. 모델이 다른 발췌 번호를 고르면 그 수치가 실제로 들어 있는 발췌로 다시 연결하고, 어느 발췌에도 없는 수치는 실패로 남긴다.
- YouTube 연결·채널 고정·테스트 모드 토큰 만료: [docs/YOUTUBE.md](docs/YOUTUBE.md)
- AI 진행자(아나운서) 기능과 관련 모델은 2026-11-08에 제거했다. 영상은 사진 배경 + 큰 자막 + 내레이션으로만 구성된다.


**세상의 이슈, 60초면 충분해.** 로컬 Mac에서 뉴스 후보 수집 → 근거 확인 → 대본 편집 → 영상 제작을 진행하는 개인용 스튜디오.

Python 3.12 + FastAPI/Jinja2 + Vanilla JS + SQLite를 유지한다. 기존 Ollama·로컬 TTS·Pillow·FFmpeg 파이프라인을 재사용하며 유료 AI API와 외부 호스팅을 사용하지 않는다. 외부 연동은 사용자가 연결한 YouTube 비공개 업로드뿐이다.

## 서버 시작·종료

```sh
cd ~/workspace/headline60
./start.sh                 # Ollama 확인 → API 기동 → health 확인 → 관리 화면 열기
./status.sh                # 정상 여부, 관리 소유권, PID 확인
./logs.sh                  # 최근 API/Ollama 로그
./logs.sh --follow         # 로그 계속 보기 (Ctrl+C로 로그 보기만 종료)
./restart.sh              # 직접 관리하는 서버 재시작
./stop.sh                 # 직접 기동한 프로세스만 안전 종료
```

[관리 화면](http://127.0.0.1:8060) · `/health` · 환경 진단 `/api/diagnostics`.
터미널이 닫혀도 관리 서버는 유지된다. 재부팅 후에는 `./start.sh`를 다시 실행한다. 로그인 자동 시작이나 launchd 등록은 하지 않았다. **컴퓨터 잠자기와 터미널 종료는 다르다.** OS가 잠들거나 앱 연결이 끊어지면 진행이 중단될 수 있으므로 깨어난 뒤 상태와 작업 재개를 확인한다.

중복 실행을 막고, 기존 독립 Ollama를 재사용한다. 종료는 포트 번호가 아니라 `.run` 기록의 PID·전체 실행 명령·시작 시각·고유 instance를 대조한다. 소유권이 없는 Ollama/API와 재사용된 PID는 종료하지 않는다. 오래된 기록은 무시하며 로그는 `logs/`에 저장한다. 최초 서버가 기존 `dev.sh` 등으로 독립 실행 중이면 외부 서버로 표시되며 자동으로 소유권을 가져오지 않는다.

`./start.sh --no-browser`와 `./restart.sh --no-browser`는 브라우저 열기 생략 옵션이다. 전경 개발 실행용 `./scripts/dev.sh`, `./scripts/ollama.sh`도 유지했다. 기본 Python·Homebrew 링크 변경이나 sudo는 필요하지 않다.

## 설치와 실행 환경

앱의 기존 Python 3.12 `.venv`와 `uv.lock`은 유지한다. 최초 준비가 필요한 컴퓨터에서는 도구 버전을 먼저 확인하고 없는 것만 설치한다. `.env.example`을 복사하는 것은 설정 변경이 필요할 때만 한다.

```sh
uv sync --frozen
# 기본값 변경이 필요할 때만
cp .env.example .env
```

MLX 음성은 **별도** `runtime/tts/.venv`와 잠금 파일을 사용한다. 이번에는 `mlx-audio==0.6.2`와 Qwen3-TTS 1.7B CustomVoice 8bit 한 모델만 설치했다. 이미 설치한 이 프로젝트에서는 다시 다운로드할 필요가 없다.

```sh
# 별도 TTS 환경을 새로 구성할 때만
uv sync --project runtime/tts --frozen --python .venv/bin/python
runtime/tts/.venv/bin/python runtime/tts/download_model.py
```

다운로드 스크립트는 모델 크기와 여유 디스크를 먼저 확인한다. 추론 중에는 모델을 자동 다운로드하지 않는다. 가중치는 `data/models/qwen3-tts-1.7b-8bit/`에 있고, 신경망 추론은 별도 프로세스로 실행한 뒤 종료해 메모리를 해제한다. 다른 TTS 모델은 추가 설치하지 않았다. 과거 Phase 3의 MuseTalk·FLUX 환경은 2026-11-08에 삭제했다.

## 브라우저 작업 흐름

1. **뉴스 탐색:** 카테고리·키워드·최근 1/3/7일을 선택하고 Google News RSS를 수집한다. 원문 URL·제목·출처·발행일을 저장하고 동일 URL을 중복 제거한다. 유사 제목을 묶어 자체 추천 점수로 정렬한다.
2. **기사 선택:** 한 건 또는 관련 기사를 여러 건 선택해 ‘선택한 기사로 대본 준비’를 누른다. URL 직접 입력도 가능하며 본문을 자동 수집하지 않는다.
3. **근거 확인:** 공식 자료 URL, 발표일, 확인일, 직접 요약한 주장, 짧은 근거, 적용 조건을 입력한다. 공식 페이지 미리보기는 등록된 공식 기관·제조사 HTML 한 건만 읽고 원문 전체를 저장하지 않는다. PDF 등은 원문을 직접 열어 짧은 근거를 입력한다.
4. **대본 생성:** 원문 확인란을 선택하고 저장한 근거로 Qwen3 대본을 생성한다. RSS 제목은 사실 근거가 아니며 모델 입력에서 제목 수치를 제외한다. 근거가 없거나 검토가 안 됐으면 생성을 보류한다.
5. **대본 편집:** 제목·후킹·전체 대본·장면별 내레이션·설명·순서·길이·시각 자료·주장별 출처·설명·해시태그를 수정한다. 전체 대본 편집은 한 줄당 한 장면이고 ‘장면에 적용’ 후 저장한다. 첫 장면은 3초, 전체 합계는 30/60초여야 한다.
6. **검토 승인:** 중요한 숫자·기준일·조건·의약품 효능 등을 원문과 직접 대조한다. 사실과 해설을 구분한다. 저장한 최신 버전만 승인할 수 있고 수정하면 승인이 해제된다.
7. **음성·발음 검토:** 영상 제작 화면에서 macOS 또는 MLX 엔진과 검증된 프로필을 선택한다. 저장된 5~10초 샘플을 듣거나 직접 입력한 문장으로 새 샘플을 만든다. Female News Anchor 기본은 성숙하고 차분한 톤을 지시한 Sohee 프로필이다. 발음용 대본은 표시 원문과 별도로 자동 정규화하며 필요하면 장면별 구절 한 줄씩 수정한다. 지원하지 않는 남성 한국어 프로필은 선택지에 노출하지 않는다. 실패하면 오류를 표시하며 다른 목소리로 몰래 대체하지 않는다.
8. **영상 생성:** 현재 승인된 버전으로 렌더링한다. 상태·실패 단계·오류·진행 단계를 화면에서 확인한다. 영상 미리보기, MP4, 대본·자막·출처, 게시 자료 ZIP을 내려받는다.

**실제 게시용 기본 출력은 720×1280, 30fps, H.264/AAC MP4**다. 1080p는 선택 옵션으로 보존한다. 이번 Phase 2에서는 720p 최신 뉴스 영상을 실제 생성했고 1080p를 새로 렌더링하지 않았다.

제작 내역의 **대본 보기**는 영상에 사용된 전체 내레이션을 한 화면에 표시하고 복사·TXT 저장을 제공한다. 원본 JSON도 별도로 유지한다. 새 구절 자막 영상의 **자막 편집**에서 문구·시작/종료 초·강조 단어를 수정하면 새 대본 버전이 만들어지고 승인이 해제된다. 저장·재검토·렌더링 후 새 결과를 얻으며 기존 완료 영상은 보존한다.

‘렌더링 완료’는 미디어 출력 성공이다. ‘사용자 검토 버전’은 원문 대조·대본 검토 절차를 거쳤다는 뜻이며 자동 사실 검증을 의미하지 않는다. 예전 설명형 테스트 세 개는 **제작 내역 → 이전 설명형 테스트 기록**에 별도로 접어 두었다.

## 검토와 콘텐츠 제한

- 근거 없는 숫자, 끊어진 주장–출처 연결, 한자 혼입, 장면 길이 오류 등은 검토 승인 단계에서 차단한다. **이 검사는 휴리스틱이며 의미·수치 단위의 정확성이나 문장과 근거의 함의를 자동으로 증명하지 않는다.** 사용자가 출처와 내레이션을 직접 검토해야 한다.
- 특히 계획 발표가 실제 성과를 입증하거나 ‘성과가 없다’를 입증하는 것은 아니다. LLM이 만든 원인·전망·효능을 근거 없이 승인하지 않는다.
- 건강·부동산·자동차 카테고리는 등록된 공식 도메인의 자료가 필요하다. 기본 목록은 `app/news/evidence.py`에 있으며 모든 제조사·기관을 포괄하지 않는다.
- RSS URL은 Google 중계 주소일 수 있다. 같은 URL의 중복은 제거하지만 다른 중계 주소/원문 주소의 동일 기사까지 항상 식별하지는 못한다.
- 유사 제목 분류와 출처명 수는 참고용이며 동일 이슈·독립 취재를 보장하지 않는다. 추천 점수는 검색량·조회수가 아니다.
- 언론사 사진·영상은 가져오지 않는다. 새 릴스는 사용 권리를 확인한 사진/영상과 그래픽, 출처·기준일이 연결된 비음수 막대 비교 차트를 지원한다.
- 새 음성 프로필의 자막은 각 구절을 실제 합성한 음성 길이로 계산하고 최종 배속에 맞춰 조정한다. 기본 두 줄과 720p 안전 영역·강조를 지원한다. 단어별 강제 정렬은 아니며 구절 안에서의 정확한 싱크를 보장하지 않는다. 기존 장면 자막 영상은 보존한다. 음성과 숫자 발음의 자연스러움은 게시 전 직접 청취한다.
- 네이버 API, 실사형 AI 아나운서·의상·헤어·립싱크는 아직 연결하지 않았다. 현재 영상은 음성·그래픽·자막 기반이다. 신경망 TTS 프로필의 기술적 실행 성공은 사람이 느끼는 자연스러움·연령감까지 보증하지 않는다.

## 저장·재사용·복구

- `data/jobs.sqlite3`: 기존 jobs 테이블을 유지하면서 상세 정보 컬럼과 뉴스·대본 테이블을 추가한다. 예전 제작 이력은 보존한다.
- `data/drafts/<id>/`: 대본 수정 전 버전 스냅샷과 각 Ollama 원본 응답. 실패 응답도 보존한다.
- `data/cache/{tts,cards,segments}/`: 콘텐츠 해시로 장면별 재사용. 같은 내레이션·목소리는 음성을 재사용하고, 카드·음성·길이가 같은 장면은 인코딩 결과를 재사용한다. 최종 파일은 새 작업 폴더에 저장한다.
- `outputs/<job_id>/`: `output.mp4`, `script.json`, `metadata.json`, `sources.json`, `subtitles.srt`, `job.json`, `job.jsonl`, `timing.json`, `ffprobe.json`, 원본 뉴스·근거 스냅샷 및 장면 자료.
- 동일 대본 버전의 중복 생성은 기존 작업을 반환한다. 새 편집 버전은 새 결과를 만들며 완료 파일을 덮어쓰지 않는다.
- **취소**는 실행 중인 미디어 프로세스를 종료하고 cancelled로 저장한다. **재개**는 완료된 대본·음성·카드 단계를 건너뛴다. 서버 재시작으로 중단된 UI 작업도 이력에서 재개할 수 있다.
- 한 프로세스의 단일 작업 큐와 프로세스 간 파일 잠금으로 무거운 추론·미디어 작업을 직렬화한다. Ollama는 추론 후 언로드한다.
- 모델·음성·인코더 등의 기본 설정이 달라진 작업은 원래 설정으로 복원하거나 새 작업으로 생성한다. 캐시 자동 정리는 아직 없으므로 디스크 사용량을 관리한다. 영상 작업 시작 시 1GiB 미만이면 중단한다.

**265개 테스트**: 기존 33개를 포함해 서버 소유권·오래된 PID·중복 실행·복구, 두 엔진의 명시적 실패 처리, 한국어 발음 정규화, 오디오 검사, 구절 자막 타이밍·안전 영역·편집 검증을 추가했다. 초기 33개 검증 범위: 기존 16개 + 뉴스/대본/작업 API, XML·URL·날짜·중복·유사 그룹, 근거/숫자 검사, SQLite 마이그레이션, 요청 토큰/Origin, 수정·승인 해제, 중복 제작 방지, 취소/재개 상태, 음성 부분 재사용 회귀 테스트.
자동 테스트의 모델·미디어 Mock과 실제 Google RSS·Ollama·TTS·FFmpeg·브라우저 통합 실행은 구분해서 기록한다.

선택적 메모리 관측 도구 `scripts/measure_resources.py`는 앱 PID 자식과 Ollama 프로세스의 ps RSS를 합산한다. 공유 메모리 중복 집계가 가능하고 Metal·물리 통합 메모리 피크 지표가 아니며, 짧은 단계는 샘플에서 빠질 수 있다.

## Phase 2 비교 자료와 알려진 한계

- 최신 720p 영상: `outputs/20261028T235001-1dbcb061/output.mp4` (동일 음성 재사용 후 자막 강조·디자인 수정).
- 최초 신경망 통합 영상: `outputs/20261028T232115-8e309044/output.mp4` (음성 캐시 없이 생성).
- 기존 macOS 영상: `outputs/20261028T222251-ef40140e/output.mp4`.
- 성숙한 톤 샘플: `data/tts_samples/mature/sohee-mature.wav`. 스타일 비교: `data/tts_samples/styles/`.
- 60초 발음 비교: `data/benchmarks/tts-macos-yuna-news-60-20261028T232737/sample.wav`, `data/benchmarks/tts-female-news-60-20261028T232753/sample.wav`.
- 벤치마크는 날짜·금액·비율·모델명 발음을 점검하는 예시이며 실제 뉴스 수치가 아니다. `scripts/benchmark_tts.py --profile female-news --seconds 60`으로 재측정할 수 있다.
- 자동 정규화는 날짜·금액·비율·수량·일부 약어를 보수적으로 처리한다. 낯선 차량/지역/아파트 이름과 문맥이 불분명한 수치는 원문을 유지하므로 직접 확인한다. 발음용 대본도 최종 승인 전에 검토한다.
- 소리 크기·무음·클리핑·토큰 한도 검사와 loudness 정규화는 구현했지만 음성 의미·발음·감정의 적절성은 자동 판정하지 않는다.
- 모델별 성능은 원음 길이와 캐시 여부가 다르므로 최종 720p 재렌더링 시간과 캐시 없는 합성 시간을 혼동하지 않는다.
- SQLite는 계속 사용한다. `?` 바인딩, `PRAGMA table_info`, `INSERT OR IGNORE`, `rowid` 의존 및 JSON TEXT 저장은 향후 PostgreSQL 전환 때 바꿔야 할 부분이다. 파일은 DB에 넣지 않고 경로와 메타데이터만 저장한다.
