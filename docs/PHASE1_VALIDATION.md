# Phase 1 검증 — 2026-10-28 (Asia/Seoul)

## 기존 상태와 이번 범위

기존 Python 3.12/FastAPI/Jinja2/SQLite, Ollama qwen3:4b, macOS say, Pillow, VideoToolbox/FFmpeg와 설명형 CLI·실패 단계 재개를 재사용했다. 기존 16개 테스트와 예전 영상 파일을 유지했다.

기존 UI는 환경 진단과 CLI 안내 중심이었다. RSS·근거 저장·대본 검토·브라우저 생성 제어가 없었고, 완료 상태만으로 대본 검토 여부를 구분하지 못했다. 이번에는 뉴스 작업과 이전 설명형 테스트 목록, 렌더링 성공과 원문 검토 상태를 나누었다.

이번 최종 검증은 사용자의 추가 지시에 따라 **720p까지** 진행했다. 1080p를 새로 렌더링하지 않았다. 기존 렌더러 기능은 보존했다.

## 코드 변경

- `app/news/feeds.py`: 6개 카테고리, 키워드, 최근 1/3/7일 RSS, URL 정규화·동일 URL 제거·유사 제목 그룹·자체 추천 점수.
- `app/news/evidence.py`: 등록된 공식 도메인의 단건 HTML 미리보기, 크기 제한·공개 주소/리디렉션 확인. 기사·사진 대량 수집 없음.
- `app/studio_models.py`, `app/studio_store.py`: 뉴스·근거·대본 버전 저장, 확인/승인·수치·출처 연결·장면 길이 검증.
- `app/llm/news_writer.py`: 검토한 근거만 사용하는 뉴스 대본 생성, 구조화 JSON, 실패 원본 응답 보존, 추론 후 언로드.
- `app/jobs/store.py`: 기존 jobs 테이블 보존 및 상세 컬럼 마이그레이션.
- `app/jobs/manager.py`: 단일 로컬 큐, 브라우저 생성/승인/렌더링/취소/재개, 중복 작업 방지.
- 기존 `pipeline.py`, `tts/macos.py`, `media/cards.py`, `renderer/ffmpeg.py`, `process.py`, `script/models.py`: 편집한 대본 입력, 뉴스 출처·장면 시간, 콘텐츠 해시 캐시, 미디어 프로세스 취소, 단계 시간 측정 확장.
- `main.py`, `templates/index.html`, `static/{app.js,style.css}`: 대시보드·뉴스 탐색·영상 제작·내역·설정, 미리보기·자료 ZIP, 토큰/Origin/Host 보호.
- `profiles.py`: 후속 음성·성인 가상 진행자 프로필 데이터 계약만 추가. 실제 앵커/의상 기능 없음.
- `tests/test_news_workflow.py`: 추가 회귀 테스트. `scripts/measure_resources.py`: 선택적 RSS 메모리 샘플러.
- `README.md`, `AGENTS.md`, 이 문서 및 `ASSETS.md` 업데이트. 시스템 도구·모델 추가 설치 없음.

공식 도메인 경계, 유사 기사와 추천 점수, 근거·수치·출처 연결,

## 실제 통합 실행

브라우저에서 다음 흐름을 직접 수행했다:

1. **뉴스 탐색**에서 IT·기술 / `해양수산 AX전략` / 최근 1일 검색.
   실제 Google News RSS **25건**, 단순 유사 제목 **19개 묶음** 수집.
2. 정책브리핑과 다른 매체의 관련 기사 **2건 선택** 후 대본 작업 저장.
3. 근거 없이 생성 요청 시 ‘RSS 제목만으로 대본을 만들 수 없습니다’ 오류로 보류되는 것을 확인.
4. 공식 HTML 미리보기에서 다음 자료의 본문·발표일·이용 조건을 확인:
   [정책브리핑 / 해양수산부, 2026-10-28](https://www.korea.kr/news/policyNewsView.do?newsId=148974483).
   추진 분야, 무인 선박 검증 계획, 항만 자동화 실증·확산 계획을 독자적으로 요약한 핵심 주장 3개와 짧은 근거를 기록했다.
   사진·표·영상은 재사용하지 않았고 확인되지 않은 수치는 영상에 넣지 않았다.
5. 실제 Ollama 요청 첫 시도에서 제목에 있던 근거 밖 수치 유입을 차단했다.
   RSS 제목을 모델 입력에서 제외한 뒤 실제 추론을 다시 수행해 대본 생성 성공.
6. 생성 대본의 ‘성과가 없다’는 단정을 원문이 입증하지 않으므로 직접 수정했다.
   후킹 문장을 3초 분량으로 줄이고 장면별 내레이션·제목·설명·출처 연결·사실/해설을 편집해 **버전 5**로 저장·승인.
7. 브라우저 **영상 생성**으로 Yuna 음성 6개·카드 6개·30초 720p 영상 생성 시작.
   합성 중 **제작 취소**로 `cancelled` 기록을 확인한 뒤 **실패 단계부터 재개**.
   같은 작업 ID에서 음성·카드 단계를 건너뛰고 합성·검증을 마쳐 완료.
8. ffprobe와 전체 디코딩 통과. 브라우저에서 `paused=false`, 약 19.27초, `readyState=4` 확인.
9. HTTP Range 실제 응답 **206**, `bytes 0-1023/4423848` 확인.
   게시 자료 ZIP 실제 응답을 열어 MP4·대본·자막·출처·메타데이터·게시 텍스트 포함을 확인.
10. Ollama `/api/ps`에서 `models=[]` 확인. 모델이 작업 이후 언로드됨.

## 남은 사항과 후속 단계

- LLM은 근거가 있어도 의미를 과장할 수 있다. 휴리스틱 숫자 검사는 사실 검증을 대체하지 않는다. 게시 전 원문 대조·음성 청취가 필수다.
- 이번 최신 뉴스 통합 결과는 30초 720p다. Phase 1에서 60초 또는 1080p 뉴스 통합 영상을 새로 만들지는 않았다. Phase 0에서 검증한 기존 길이·해상도 지원은 보존했다.
- 자막은 장면 단위이며 단어별 강제 정렬은 없다. 전체 음성을 사람이 듣는 품질 평가는 아직 완료하지 않았다.
- Google RSS 중계 URL의 원문 canonical 통합, 정교한 주제 묶음, 네이버 API, PDF 자동 처리, 실제 차트는 미구현이다.
- 캐시 자동 정리, 대본 작업 삭제/보관 UI, 여러 서버 인스턴스 운영은 추가 작업이다. 현재는 로컬 단일 서버 전제다.
- Phase 2는 별도 환경에서 Qwen3-TTS CustomVoice의 5초 한국어 샘플을 고정 화자로 테스트하고 발음·스타일 지시·시간·메모리를 측정한다. macOS TTS fallback은 유지한다.
- 공식 문서와 MLX 구현을 먼저 대조하며 0.6B에서 말투 지시를 지원한다고 가정하지 않는다. 모델 다운로드는 별도 동의 후 한 종류씩 진행한다.
- AI 진행자·얼굴 일관성·의상·립싱크는 설치·실행 검증하지 않았다. 검증되지 않은 프로필은 선택지로 노출하지 않는다.
